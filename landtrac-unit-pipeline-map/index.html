Discrepancies & corrections vs. the original diagram

Prefect is a control plane, not a data-path stage. landtracunit-v3 (Prefect) does not touch Kafka or move records. It drives the dataset-materialization-service lifecycle (Materialize → Prepublish → Verify counts → Publish → Clean) via the DSM API. Real data path: Airflow producer → Kafka → DSM consumes/materializes.
6th publish target (undocumented). The Prefect flow's cache_config writes results back to Hendrix gis_exports.bdd.batch_landtracunit_v3, in addition to the five originally drawn (Direct Access, DIBI, Prism, Elasticsearch, DS9).
Version drift. Prefect flow default is v3.2.7; the DSM-spec links in the same file point at v3.2.6.
unit-polygon-id is manual. Not scheduled on the VM — ad-hoc ML unit clustering the GIS team runs by hand (hardcoded desktop file-gdb, single county). Drawn dashed/amber.
wellid-updates and daapID-update overlap. daapID-update (Py3, Fri) is a newer narrow split of wellid-updates (Py2, Sun) — both backfill API10/daapUnitID on UPP; wellid-updates also sets WellID.
Two point-ingestion paths into UPP. direct-access-unit-point-feed (external DA V2 API, weekly) and up-upp-sync (internal unit_point layer). Note: up-upp-sync is not on the VM Task Scheduler — its trigger is unconfirmed. The polygon side flows the other way: landtrac-unit-upload pushes QC'd polygons to the Div1 hotfolder loader.
reconcile-post-all is SDE maintenance, not a points reconciler. Despite the pos in the task name (= "post"), it runs ArcSDE reconcile → post → compress → rebuild indexes, committing SDE.EDITORS edits into SDE.DEFAULT daily 3am. Shared across the lease, unit, and landgrid SDEs — it's the step that makes GIS-team versioned edits visible to the producer.
